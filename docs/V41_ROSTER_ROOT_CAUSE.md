# v0.41 캐릭터 목록 성별/직업 깨짐 원인

0.40의 가정은 틀렸다. 문제 화면은 단일 문자 렌더러에서 3바이트를 하나씩 그리는 경로가 아니라, 먼저 20바이트 고정 행 문자열을 만든 뒤 일반 문자열 렌더러로 출력한다.

두 중복 생성 루틴은 다음 위치에 있다.

- `VBASE.OVR` 성별 메시지 기준값: 파일 오프셋 `0x5FA3`
- `VPCMK.OVR` 성별 메시지 기준값: 파일 오프셋 `0x6975`
- 직업 기준값은 각각 `120`이며 첫 3바이트를 복사한다.

행 끝부분은 원래 다음 형태다.

```text
[gender 1 byte] '-' [profession 3 bytes] NUL
```

한국어 메시지 140/141은 각각 `남성`, `여성`이며 첫 글자부터 `17 xx xx` 3바이트다. 첫 1바이트만 복사하면 행은 다음과 같이 된다.

```text
17 2D 17 xx xx 00
```

`resident_string`은 첫 `17`을 한국어 escape로 해석하고 뒤의 `2D`와 다음 `17`을 pair로 소비한다. 이 순간 성별뿐 아니라 직업 escape 경계까지 사라져 뒤쪽 전체가 깨진다.

게임 데이터에는 기존 ASCII 성별 테이블이 있다.

- message 455: `MF` (첫 바이트 `M`)
- message 456: `FMPTRABPVBLSMN` (첫 바이트 `F`)

따라서 목록 생성 루틴의 기준 메시지만 `140`에서 `455`로 바꾸면 기존 1바이트 필드가 `M/F`가 되고, 바로 뒤 직업의 `17 xx xx`가 정상 경계에서 시작한다. 다른 성별 선택 화면의 `남성/여성` 번역은 그대로 유지된다.

v0.41은 공개 v0.39를 직접 기준으로 하며 `VBASE.OVR`, `VPCMK.OVR`에서 각각 3바이트만 변경한다. 0.40의 resident_char 실험은 포함하지 않는다.
